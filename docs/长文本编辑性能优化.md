# 长文本编辑性能优化（v0.6.40）

## 使用变化

- 停止输入约300毫秒后，在后台更新解析；输入框可继续编辑。
- 只重新解析有变化的账目，未改动的账目复用结果。仍按完整账目解析，保留玩家、市场、跨行金额等上下文规则。
- 原文高亮复用未修改行；中奖、定位、字体与折行继续同步。
- 待处理每页30项，支持上一页、下一页。点击原文会自动跳到相关待处理所在页，不再为定位最后一条而加载前面所有条目。
- AI缓存读取合并到输入停止800毫秒后；自动核验仍按原有设置执行，整单核验内容的准备也在后台完成。编辑时不重复读取核验历史，隐藏的AI页面不构建核验列表。
- 后台解析未完成时，结果底部显示“正在更新解析，金额为上次结果”。中奖标记继续遵循原有规则，仅标记与当前原文一致的结果。

## 数据一致性

后台结果仅在原文、日期、玩家、名称、核验解释与请求时一致时采用。连续编辑、切换账目、清空或关闭空间后，过时的后台结果会被丢弃。最多运行一个后台任务，后续编辑合并处理，避免排队计算大量旧版本。

保存仍独立使用当前原文；关闭和切换空间继续等待保存完成。后台不可用时回退到原有本地解析，不修改计费、中奖、赔率或退水规则。

本次优化未更改数据库结构，也未修改规则版本或清除已保存的AI核验记录。

## 验证

- 自动测试验证账目缓存失效条件、未修改账目复用、完整上下文金额一致、3000行编辑只重新分词变化行、后台任务异常与销毁。
- Mac隔离启动检查使用3000条待处理内容，验证列表分页、远距离定位、连续输入不逐字访问AI缓存、解析期间改字后仅采用新结果，以及切换账目后原文保存。
- 输入耗时记录在 `desktop-client/reports/mac-startup-0.6.40.json` 的 `editingPerformance` 字段。该值为合成数据下从输入事件到Vue更新及布局读取的耗时，不代表所有账目的最坏耗时或完整屏幕绘制时间。
- 极长文本仍沿用原有普通显示限制；主动点击定位需要即时新结果时，仍可同步解析。
