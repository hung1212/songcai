# AI核验与最近开奖使用说明

版本：0.4.4，日期：2026-10-05。

## 标准解析

`新奥，牛鼠数各十五` 在2026马年按8个特码号码各15元计算，共120元。前一行是平特或连肖时，也会终止旧玩法继承；同一玩家的市场继承继续保留。

`特肖牛鼠各十五` 按两个特肖计30元；`特肖牛鼠数各十五` 同时存在逐肖和逐号依据，显示冲突。财务数字如“壹拾伍圆”可直接转换为15元。农历生肖和固定五行沿用已有口径。

## AI核验

菜单新增“AI核验”，针对当前投注账目。微信收件箱每份待核对记录也有“AI核验与解释确认”入口，使用同一套设置；图片和收藏先本地OCR，原图仍需人工核对。

1. 在桌面软件的“接口设置”中填写完整请求地址、模型名称和密钥。首版支持 Chat Completions 兼容协议，服务商须支持JSON对象响应。密钥由系统加密保存在本机，导出账目不包含密钥。
2. 确认发送范围后启用自动核验。默认核验疑难与可疑表达；可改为全部投注，也可以手动核验整单。停止输入约1.5秒后启动，每批最多5行，并发最多2份文档。
3. 核验片段、必要的市场／玩法上下文、规则及业务日期会发给配置的服务商。不会主动附带玩家姓名、通讯录或原图；片段中原有的文字仍会发送。接口默认关闭。
4. 意见一致时记录一致；意见不同或无法确定时显示候选、原文依据和本地计算的金额。选择“采用这个解释”或核对本地规则。原文另行保留，不会被AI替换。
5. 同一玩家、同一天、相同片段且继承市场／玩法一致的重复项，可以一次确认多行。确认只作用于当前文档；不跨玩家套用。
6. 可将已采用候选保存为“仅本玩家”或“所有玩家”的完整表达规则。同样的表达中，玩家专用规则优先于通用规则，同范围优先最近确认的规则。复用时重新进行本地校验与生肖展开，可以停用。

首版表达记忆严格匹配完整原句（包括金额）及有效上下文，不执行任意子词批量替换。变换金额或写法后重新核验。日期改变会重新校验并按新日期展开生肖。金额必须能从明确的原文数字验证；“一皮”这类未确定的金额单位需要先明确金额，不能让AI补造。跨行共用金额和撤改指令不能由单行候选覆盖，需先整理原文。

原文、业务日期、默认玩家或规则版本改变后，旧解释失效。未结束的旧请求会取消或丢弃。候选、决定及历史保存在本地SQLite；收件箱确认后仍遵守原有防重复入账规则。接口超时、断网或达到请求上限时，本地确定的投注继续可用，必核项保持待处理。重试也计入每日请求上限；缓存命中不发网络请求。

AI解释含义，程序负责金额、展开号码及赔率算术。未解决的解释差异不能标记为赔付完成。“采用本地规则”也不会消除原本的缺金额、玩法冲突等错误，需要修改原文。

## 本账目中奖数据

进入“投注账目 → 中奖数据”后，默认读取新、旧、港各自最近一期，并在桌面版后台获取最新记录；短时间重复打开共用获取结果。香港未必每天开奖，可以与新、旧市场采用不同日期。

- 开奖日期与账目业务日期分开。原文的生肖展开号码始终按账目业务日期生成；开奖中奖判断与当年生肖赔率按选定开奖日期计算。
- “选择开奖日期”切换为准确日期，缺少该日记录的市场保持待结算，不拿其他日期顶替。“各市场最近开奖”恢复默认模式。
- 同一期的有效网站结果一致时，默认选择核对列表第一来源。正码顺序不同但六个号码相同、特码相同，视为一致。
- 依照已启用来源顺序排列，默认新市场 macaujc.com、旧市场 lamlhc.com、香港香港马会在前；该网站没提供目标期时依次选择后续来源。同一上游的网站仍只算一个独立核对来源。
- 多站有冲突时默认不采用，需要在“核对／选择开奖依据”中明确采用一个结果；单一独立来源也保留人工采用步骤。新增冲突证据会使之前的确认失效。
- 每个市场显示实际日期、期号、号码和来源。只计算当前账目，赔付历史仍独立归属该账目，已保存版本不会随新原文或新开奖改写。

旧“开奖与赔付”页面仍按业务日期进行整批结算。网站历史覆盖不足时，选择较早日期可能缺期，可在该页面人工核对并补录。元旦当年暂无开奖记录时，“最近开奖”会尝试上一年记录。
