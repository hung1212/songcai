# 账目录入界面优化方案对比

日期：2026-10-07。基于 v0.4.14 界面、代码及用户提供的账目列表截图。

本文件保留设计阶段的方案比较。2026-10-07 已按选中的“录入优先”方向实现 v0.5.0，见《录入工作台使用说明》。比较中的空间尺寸为设计建议。

## 使用重点

日常主要路径是：找到玩家账目 → 粘贴或编辑投注原文 → 核对金额、处理有争议的内容 → 切换下一份账目。

原文编辑和账目切换应始终容易到达；中奖、号码分布、全局统计保留完整入口，根据使用时机展开。

## 现状与影响

| 现状 | 对日常录入的影响 |
| --- | --- |
| 功能导航、规则资料与账目名单共用一条侧栏；侧栏宽度按窗口为 160、175 或 211px | 截图中名称容易截断，较长且前缀相同的名字难区分；低频菜单挤占账目空间 |
| 名单限制为最大 42vh，侧栏本身也可以滚动 | 找账目可能需要在不同滚动区域之间切换，搜索与名单的位置也可能变化 |
| 编辑区上方有宣传标题、范围切换、四张金额卡、净输赢块、标题和日期等配置 | 进入账目后，真正的原文输入区域距离顶部较远 |
| 常规双栏中，结果区分配的宽度多于编辑区；窗口不超过 1000px 时上下排列且编辑区高度 270px | 长投注需要更多横向或纵向滚动，笔记本窗口尤其明显 |
| 当前放大编辑采用模态窗口 | 放大后无法直接操作背后的账目名单，要先收起再换账目 |
| 原文字号 12px，账目名称 11px，次要金额多为 10px | 长时间查看号码和金额比较吃力 |
| 已经自动解析与自动保存，但仍突出“解析文本”“保存到数据库” | 容易让人误以为每次录入后还需点击才能生效 |
| 账目净输赢展示依赖最近开奖记录 | 录入时仍需要优先看本单已计投注与待处理；试算结果应清楚标明开奖依据 |

## 三种方案

| 方案 | 页面组织 | 优点 | 代价／边界 | 适用 |
| --- | --- | --- | --- | --- |
| 保留现有布局 | 加宽侧栏、压缩顶部卡片、增大字体和编辑高度 | 学习成本低，改动较小 | 菜单与账目依然争空间；放大后频繁切单的问题仍需另外解决 | 希望小幅调整、保持熟悉布局 |
| **录入优先工作台（推荐）** | 顶部功能导航；左侧独立账目名单；中央大原文；结果面板按需展开 | 编辑空间最大，名单一直可用，改原文与核对疑点可以连贯完成 | 需要整理页面结构、保存每份账目的编辑位置 | **每天多次粘贴、修改、切换玩家账目** |
| 表格选单 | 以名称、投注、净输赢、待处理等列展示账目，选中行后在下方或侧边编辑 | 查金额、排序、批量核对最直接 | 表格持续占空间；小窗口中原文编辑受挤压 | 开奖后集中查账、对比所有玩家 |

建议以“录入优先工作台”为账目默认入口，把“表格选单”的长处放在现有“全部账目统计”页面。无需给日常录入增加三个需要反复切换的工作模式。

## 推荐布局与交互

### 功能入口

顶部保留：账目、微信收件箱、全部统计、开奖赔付、特码集合。赔率、生肖、AI 核验与帮助放入“更多”，待处理中的 AI 入口仍可直接到达对应账目。

软件启动恢复上次账目。进入账目直接显示原文，不先经过统计页。

### 账目名单

- 独立使用整个内容区高度，搜索、新建和列表工具固定在顶部；仅名单滚动。
- 建议默认宽 260px，支持在约 220–360px 间拖动调宽并记忆。长名称悬停可看完整名称，选中账目的标题在中央完整显示。
- 两行展示：第一行名称和明确的“待处理 N”标签；第二行显示“已计 ¥330 · 试算输 ¥330”等金额状态。空账目、待结算分别标注，不能当成零输赢。
- “已计”仅指已进入汇总的投注，有待处理时不称为完整总额。净输赢保留玩家视角与“试算”标志，开奖日期可查看。
- 选中态使用清楚的底色与标记，提高名称对比度，状态同时用文字表达。
- 默认继续使用手动排序。最近编辑、待处理等作为可选筛选／排序；编辑时不自动改变名单位置。非手动排序时不直接改写手动顺序。
- 使用独立拖动手柄，普通点击负责选中，降低切单时误拖动的可能。
- “清空全部内容”“撤销上次清空”移入始终可见的账目管理菜单；保留现有确认与可撤销能力。

### 原文编辑

- 删去宣传文案与高卡片，把当前账目名称、业务日期、保存状态压成紧凑标题栏。
- 标题留空自动命名、同名覆盖的既有行为保留；重命名操作中显示说明。未署名玩家放在“账目设置”，标题栏可显示当前归属。
- 默认字号建议 15px，提供 14–18px 调节；玩法／选号／金额继续采用三色高亮。
- 编辑区填满剩余高度。支持视觉自动折行，原始换行与解析行号保持不变；“整理换行”仍是明确改变文本的独立操作，可撤销。
- 粘贴继续使用现有金额分段与续行规则。默认在当前光标处插入，另设“到末尾继续录入”入口，避免中途修改时被强行跳到底部。
- 为每份账目记忆光标、选区、滚动位置。切换回来恢复该位置；从待处理进入则定位对应行。跨账目不能串用撤销历史。
- 把“放大编辑”改为非模态的“专注编辑”：收起右侧结果但保留账目名单，仍可快速换单。名单也可主动折叠，退出后恢复宽度与位置。

### 结果与待处理

- 编辑区固定一条紧凑汇总：“已计金额｜新／旧／港｜待处理数量”。编辑状态始终明确属于当前账目；跨账目合并统计统一在“全部账目统计”展示。
- 常规双栏可分配编辑区约 60%–70% 的可用工作区宽度；结果面板建议 280–360px。在 1280px 左右的窗口优先收起结果，不硬挤出过窄的原文区。
- “待处理 N”可一键打开同页结果面板，显示具体原因与对应原文。点击原因定位行，改完后更新金额与数量，不自动抢走光标或弹窗。
- 明细、中奖、号码分布在结果面板中切换；号码分布等宽内容可主动扩展。中奖数据继续保留开奖日期和依据选择能力。
- 中奖、应付、净输赢应区分待结算、试算和已保存的结算记录；原文改变后提示相应结果需要更新，不把旧赔付显示成新结果。

### 保存、解析与输入稳定性

现有自动解析约在停顿 300ms 后触发、自动保存约在停顿 650ms 后触发。界面改为持续显示“正在保存／已保存／保存失败”，减少固定主按钮；手动保存或重新解析可放在更多操作中。

切单、页面隐藏和退出等边界仍应可靠提交已有更改。保存失败需保持原文并提供重试／备份入口。中文输入法组合期间不重建编辑器、不改选区；后台更新、AI 返回、解析完成不打断输入。账目按稳定 ID 维护编辑状态，不能按可能重复的标题关联。

目前编辑后会重新解析全部账目。实施时应验证大量账目时的响应，必要时改为仅重算变化的账目并复用其他结果；处理过期任务时核对账目 ID 和原文版本。性能调整不能改变解析和计费口径。

### 快捷操作

- Mac 使用 ⌘、Windows 使用 Ctrl：例如 ⌘/Ctrl + K 打开账目搜索并用上下键选择、Enter 进入。
- 编辑框内上下键继续移动光标，不用于偷偷切换账目。
- 保留系统复制、粘贴、撤销与输入法行为。专注模式、字号、末尾录入等都有可见按钮，快捷键只作为补充。

## 建议实施顺序及验收

1. **首批：布局与阅读。** 独立名单、压缩顶部、扩大原文、字号、固定本单摘要、管理菜单收纳。
2. **随后：连续录入。** 每单位置记忆、非模态专注、末尾录入、快捷搜索、同页定位问题。
3. **最后：规模验证。** 大名单筛选和渲染、单账目解析复用、统计页表格完善。

验收以 1280×800、1440×900 及用户实际窗口为准：原文尽量可用约 500px 高度；打开账目无需先滚动整页；编辑区与名单独立滚动；编辑不闪烁、不跳光标；搜索、切单、修改和定位疑点形成连续路径。空间数值是目标，并非已测效果。

回归验证：自动命名／同名覆盖、拖动排序、业务日期与市场继承、粘贴分段、中文输入、撤销、关闭保存、待处理金额排除、中奖数据过期状态。使用合成的大账目数据验证性能，不用真实个人账目制作展示。
