# 账目空间：交互与数据隔离方案

日期：2026-10-09。状态：方案分析，尚未修改客户端功能。基于当前0.5.12代码和已采用的“录入优先”布局。

## 推荐方向

把空间作为独立账本：每个空间拥有自己的账目列表、原文、全部统计、特码集合与赔付历史。切换一次空间，相关页面一起切换。空间可以自由命名，不强制绑定日期或负责人。

建议使用顶部空间下拉切换器，位于“松财”旁，在账目、统计、特码集合等页面始终可见。新空间默认为空，可选“仅复制当前空间账目名单”；切回原空间恢复上次账目与编辑位置。

空间不等于市场。每个空间内部仍可以同时有新澳、旧澳、香港，市场继承和玩法解析规则保持不变。空间也不是多人账号或权限系统，第一版仍是本机使用。

## 入口方案比较

| 方案 | 体验 | 局限 | 建议 |
| --- | --- | --- | --- |
| 顶部空间下拉 | 所有页面可见，切换不占原文编辑区；空间多时可搜索 | 切换需展开后选择 | **默认采用** |
| 顶部空间标签栏 | 常用的2—4个空间可直接点击，来回切换快 | 空间多或名称长时挤占横向空间，并增加一行高度 | 后续可加常用空间固定入口 |
| 进入独立空间首页再选空间 | 适合大量空间的管理、归档 | 每次录入前多一层操作，打断高频切单 | 仅用于空间管理，不作为启动首页 |

不建议仅在账目列表内部增加空间筛选：全部统计与特码集合也会跟随空间，入口应体现这是整个工作区的范围。

## 主要交互

### 切换空间

顶部显示“空间 · 日常账目 ▾”。展开后展示空间名称、账目数量、当前选中标记，以及“新建空间”“管理空间”；空间较多时提供名称搜索。可用上下键与Enter选择。保留原有账目搜索快捷键。

切换流程：完成正在输入的文字 → 提交当前空间待保存的内容 → 成功后切换空间 → 更新名单与金额 → 恢复目标空间的上次账目。正常切换不弹确认框。保存失败时停留原空间，保留原文并显示重试，不让用户误以为已保存。

如果正在看全部统计或特码集合，切换后留在该页面，只更换空间数据；正在录入时恢复目标空间的账目、光标和滚动位置。切换过程中不残留原空间金额，不把旧空间最后一笔混入新空间结果。重启恢复上次空间。

### 新建空间

只要求填写名称；名称可为负责人、团队、用途或日期，不能由名称自动决定开奖日期。同名空间提示名称已存在，并可打开已有空间，不覆盖整个空间。

创建方式：

1. **全新空白空间（默认）**：账目数量0，统计与特码集合为空。展示“新建账目”“导入账目”，不插入演示账目或自动复制投注。
2. **仅复制账目名单**：复制名称、玩家绑定与手动顺序，原文为空；不复制投注、AI结果、待处理状态、赔付历史、搜索记录。适合每天沿用同一批负责人。

复制名单时可一次设置新账目的业务日期，默认当天。新空间建议复制当前空间的赔率作为初始配置，创建后独立保存，后续互不影响；这是配置复制，不是复制投注。

创建成功后直接进入新空间，输入名称按Enter即可完成。空空间允许长期存在，无需为了保存而创建一份“未命名账目”。

### 范围提示

- 账目列表顶部显示当前空间与账目数。
- 全部统计标题显示“全部账目统计 · 日常账目”，其“全部”仅指当前空间。
- 特码集合标题同样带空间名，49个号码的投注额、平均额、超额和排序仅基于该空间。
- 搜索框提示“搜索本空间账目”；最近5条访问与搜索历史分别记忆。
- 清空按钮改成“清空本空间账目内容”，确认中列明空间名和账目数。保留名单，撤销备份按空间独立保存。
- 结算单图片继续保留用户已确定的精简样式，不额外加空间名或账目名；保存图片的默认文件名包含空间名，便于自己查找。

## 隔离范围

| 数据／功能 | 建议范围 | 具体行为 |
| --- | --- | --- |
| 账目、原文、业务日期、玩家绑定 | 每空间独立 | 同一玩家名可出现在不同空间；互不覆盖 |
| 同名覆盖 | 限当前空间 | A空间“小明”覆盖A空间“小明”，不动B空间同名账目 |
| 全部统计、玩法统计、特码集合 | 每空间独立 | 页面、导出和计算均只使用当前空间；第一版不增加跨空间总计 |
| 赔率、赔付、结算历史 | 每空间独立 | 复制初始赔率后独立修改；历史不能跨空间查询或保存 |
| 所选开奖日期、来源冲突的人工决定 | 每空间独立 | A空间查看旧日期，不改变B空间；同源一致的自动选择规则保留 |
| 最近访问、搜索历史、排序、手动顺序 | 每空间独立 | 切回空间恢复原来的使用状态；默认金额从高到低，同额按显示标题字数从多到少，字数相同保留原顺序 |
| 上次账目、编辑位置、清空恢复 | 每空间独立 | 编辑位置在本次运行内切回恢复；重启恢复上次账目。原文输入框的系统撤销历史不跨空间保留，清空恢复备份独立持久保存 |
| 微信收件箱、收藏读取、导入批次与去重 | 每空间独立 | 操作开始时绑定空间，切换期间完成的内容仍进入原空间 |
| AI核验结果、玩家专属表达规则 | 每空间独立 | 同名玩家不被当成跨空间同一人；后台返回不覆盖当前其他空间 |
| 公共开奖号码、网站获取缓存、标准生肖及玩法词典 | 全软件共享 | 同期新澳、旧澳、香港公开事实可共用，避免重复抓取 |
| 本机AI连接设置、界面字号和窗口布局 | 全软件共享 | 无需在每个空间重复设置；业务数据仍隔离 |

明确保存的结算快照不因切空间或后续开奖更新而改变。若按天／期创建空间，建议结算后归档或固定该空间的开奖选择，避免再打开旧空间时误按最新一期看赔付；名称中的日期不作隐式规则。

## 空间管理

第一版建议支持创建、切换、改名、仅复制名单，以及归档／恢复。归档后从日常下拉列表收起，在“管理空间”保留名称与账目数；点击“恢复并打开”后继续查看和编辑。归档不删除数据，至少保留一个使用中的空间。优先用归档解决列表过长，不把永久删除放在高频位置。

跨空间移动／复制完整账目放到后续：移动须连同来源关联和历史处理，同名冲突需明确；复制会造成两边分别计账，不能用拖动时的隐式动作完成。第一版仅空间内拖动排序。

## 当前代码的实际影响

这次改动涉及数据模型和计算入口，不能仅对名单增加前端过滤：

- `electron/ledger-store.cjs`：当前账目标题是全局唯一，保存时删除整张账目表再写回。必须限定空间，避免保存A时删除B；标题唯一约束在各空间的独立账目库中生效，保存版本号、当前账目、清空备份同样按空间保存。
- `src/core/ledger.js`：目前不允许0份账目，需区分真正空空间和旧数据加载失败。标题自动推断、同名覆盖仅处理传入空间；所有缓存键加入空间标识。
- `src/App.vue`：目前全部统计与特码集合直接引用同一份全局结果。改成只传当前空间的账目与结果；加载、错误、空状态均以空间为单位，避免短暂展示上一个空间的金额。
- `electron/settlement-service.cjs`、`settlement-store.cjs`：读取账目、赔率、结算记录和结果哈希都须绑定空间。后端校验账目确属此空间；不能只靠界面隐藏历史。
- 收件箱、AI任务、最近访问、搜索历史等同步增加空间边界。异步任务开始时捕获空间与原文版本，完成时只更新所属空间；不依赖返回时的“当前空间”。

实际实现继续使用本地SQLite：`spaces.sqlite` 登记空间名称、归档状态及当前空间；默认空间保留原有数据库路径，其他空间在 `spaces/<稳定ID>/` 分别保存账目、赔率、赔付、收件箱和AI历史。物理隔离复用现有事务与版本校验，避免全量保存误删另一空间。公共开奖委托默认空间的开奖库共享，AI连接配置与每日用量共享。每次读写显式带空间ID并校验范围，空间名只用于显示，不当数据主键。不需要为每次切换开启一个新应用窗口。

## 旧数据与备份

升级前自动备份现有数据库。首次升级创建“默认空间”，把原来的账目、赔率、赔付历史、收件箱、导航记录等全部归入其中，保留稳定ID和原文，不丢旧数据。首次生成空间登记库前，使用SQLite快照备份已有数据库至 `space-upgrade-backup/`；备份完成才建立空间登记，失败保留原库。默认空间原库不搬移、不重写ID，旧版draft.json仍按原迁移流程保留。

v0.6.0普通账单导出／导入仅作用于当前空间，导出文件名包含空间名。收件箱备份也仅含当前空间。全空间打包备份与独立恢复入口留待后续版本；当前不要把普通账单导出当成全部空间备份。迁移失败时保留原库和备份，不初始化空数据冒充成功。

## 建议第一版验收

1. 现有全部数据升级后位于默认空间，新建空空间的账目数与统计均为0。
2. A、B各创建“小明”，分别投注300、80元；两空间金额、同名覆盖、号码分布和赔付均独立。
3. 在全部统计或特码集合切空间，页面立即显示对应空间结果，无另一空间残留。
4. 编辑中切换、输入法组合、快速连续切换、保存失败与重启恢复都不丢原文。
5. A空间清空及撤销只影响A，B的内容和清空备份不变。
6. AI返回、图片OCR、收藏读取、后台保存发生在切换后，结果仍归原空间。
7. 同一开奖缓存供两个空间使用；改变A赔率、开奖选择和保存历史，不改变B。
8. 同名玩家的最近访问、搜索、规则记忆及导入去重不串用；空间归档后恢复打开仍可查历史。

验证使用合成数据和隔离数据库，不在现有账目上试验。
