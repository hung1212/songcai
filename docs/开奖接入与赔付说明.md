## 3. 使用流程

1. 完成投注原文或微信收件箱的核对。原文业务日期须对应要结算的开奖日期。
2. 打开“开奖与赔付”，选择日期和投注来源：当前账目、该日期全部账目、微信已入账记录。三种范围独立，避免同一条记录重复计入。
3. 打开“赔率与来源设置”，确认每个市场的来源、赔率、本金口径、中奖范围和49和局规则。可多选网站；新、旧、港分别配置和保存。
4. 点击“获取开奖记录”。各网站分别显示成功、失败、最近日期和读取数量，失败保留已有历史；部分接口只有近期数据，不保证所有历史日期都有多站记录。
5. 选择当天期号，查看“网站核对”表中的前6个正码和最后1个特码。不同期号不混比，同一期日期不同也列为差异。
6. 多组来源一致时标记为“多来源号码一致”；存在差异或只有一个来源时，打开网站核对后点击对应行“采用此结果”。人工选择会记为“用户确定”。
7. 点击“计算玩家赔付”，查看应付汇总、退本金、待结算及逐笔明细。未解析原文、缺少开奖、赔率缺失等不会被当作已完成。
8. 核对无误后勾选确认并保存。未处理的开奖差异阻止保存；新增不同证据后须重新选择和计算。相同输入重复保存不新增。
9. 下方可打开历史版本或导出JSON，查看该版本原文、开奖、来源差异、采用结果和应付金额；修改当前账目不会改写已保存版本。

香港不是每日都有开奖；未开奖日期不自动代用最近一期。用户提供的新、旧是10月4日开奖，香港是10月3日，应分别按对应业务日期结算。原文期号与所选期号不符时保持待结算。

## 4. 赔率和中奖判断

默认赔率取自项目里的用户提供图片和参考页：特码47倍，赔率含本金。例如特码每号100元，中一个应付4,700元；红波整项100元，中红波按2.7倍应付270元。可改为净赢赔率口径，此时中奖本金另加一次。

| 玩法 | 当前实现 |
| --- | --- |
| 特码及分类展开 | 逐号码与特码比较。“红波各100”“天肖各100”已由解析器展开号码，按特码每号赔率判断。 |
| 特肖／一肖中特 | 看特码生肖；普通11.7倍，当年生肖9倍。默认按开奖日期的农历生肖年切换。 |
| 二至六肖中特 | 整组选项包含特码生肖即中奖；整项金额不拆成多个生肖金额。有当年生肖时使用对应特殊档。 |
| 波色／半波／大小单双／合单合双 | 整项判断特码的对应属性，按各项赔率；与“各号”展开投注区分。 |
| 二中二／三中三 | 看前6个正码；复式按中奖组合数计付。 |
| 三中二 | 恰中2个正码、恰中3个正码两档互斥，不叠加。两档倍率留空待配置。 |
| 二中特 | 两个正码、一个正码加特码分别计档。两档倍率留空待配置。 |
| 特串 | 一个正码加特码，150倍。 |
| 二至五连肖 | 每组生肖均在中奖范围内出现才中；含当年生肖的中奖组使用特殊赔率。 |
| 二至四连尾 | 每组尾数均出现才中，尾数0–9。 |
| 平特肖／平特尾 | 每个所选肖或尾出现即中，同一肖或尾重复开出仍只计一次。 |
| 平码／平特号码 | 平码默认看前6号，可配置；明确写“平特号码”的原文看全部7号。 |
| 一至五粒平特任中 | 每组任一个号码出现即中奖；同组出现多个号码仍只付一份。明确复式时计算中奖组合数。 |
| 五至十不中 | 每组所选号码全部未出现才中奖。解析器支持但参考图没提供赔率的一至四不中保持待结算。 |

连肖、连尾、平特肖／尾／任中、不中默认看全部7号，设置中可逐玩法改成前6号。生肖表按农历新年换年，2026-02-17开始01为马，2027-02-06开始01为羊；不按公历元旦切换。可选固定“马”为特殊赔率生肖，默认随农历年切换。

金额使用整数分和精确整数运算。每份中奖金额按赔率四舍五入到分，再乘份数；相同玩法的复式使用组合计数，避免展开大量组合造成卡顿。大到超出精确金额范围的结果会报错或保持待结算。

## 5. 数据保存和保护

桌面应用数据目录中新增 `settlement.sqlite`，与 `ledger.sqlite` 和微信收件箱数据库分开。数据库保存：

- 各市场多选来源、赔率、中奖范围、49规则以及设置版本。
- 每个网站的获取时间、成功／失败状态、最近一期及错误说明。
- 开奖记录、来源、来源时间与本机获取时间。同一记录重复获取不新增；同一期不同号码保留版本并显示冲突提示。
- 每次保存的原文、解析结果、选择的开奖、各站核对记录、用户选择依据、赔率、业务日期、来源范围与赔付明细快照。

保存前在主进程重新读取实际账目并校验输入摘要。试算后改过原文、赔率、开奖或核对依据时拒绝保存旧结果，必须重新计算。已保存快照不随现有账目覆盖而丢失原文。历史版本只用于对账，不累加成多笔应付。

网络请求只读取目录中固定HTTPS公开开奖地址，带超时和响应体积上限，拒绝任意重定向。不会把玩家姓名、投注原文或金额发送给开奖网站。拒绝未来开奖、重复号码、缺号、非法号码和与频道不符的记录，不降低TLS校验。

“导出本次计算与依据”包含原文、赔率、开奖记录及计算结果；暂不支持导入赔付JSON恢复整个数据库，也没有撤单、付款状态管理或自动转账。建议保留导出文件。

浏览器开发预览使用本地存储，只支持手动开奖试算；联网获取和微信已入账结算需使用桌面客户端。
