# 特码分批转出与增量补打 · 0.6.48

入口：特码集合，或单个账目的「本单结果 → 号码分布」，点击「分批打出／补打记录」。

## 日常操作

1. 选择当前日期和单个市场，按对方当前报价填写含本赔率、退水。
2. 选择「超出平均，只补差额」，或「限亏，优先已有号码」。后者填写本期最多亏损金额和最多新增号码数。
3. 复制补打清单给接收方。复制不代表实际打出。
4. 实际完成后点击「核对清单并记录已打出」，只勾选实际完成的号码，填写真实金额和报价，确认保存。也可以直接手动录入。
5. 后续投注增加时自动重算，已完成批次保留，只展示需要补打的差额。可以切换下方号码卡片为「仅已打出，当前风险」或「预计补打完成后」。

## 记录与归属

桌面版每个空间独立使用 transfers.sqlite，不把批次放进原文文件。批次包含日期、市场、已知期号、稳定账目ID、记录时玩家名称、接收方、备注、号码金额、含本赔率、退水率和保存时间。历史报价不会因新报价改变。清空投注不会清除转出，删除账目后仍纳入同日期市场的集合风险。

单账目默认归属此账目；集合可选择具体账目或「集合公共」。集合计入所有批次一次。单个玩家仅计入所属账目批次，不把公共打出重复分摊给每个玩家。若存在公共转出，玩家页面会提示到集合查看整体风险。

记录有误时可填写原因作废，保留审计记录，再录入正确批次。作废只更正账务，不会撤回实际转出。防止双击重复保存；同一请求重试不会新增重复批次。浏览器预览使用独立的浏览器存储，与桌面数据库不互通。

## 算法与范围

每个号码对应的整盘利润＝收到的特码投注－玩家退水－该号玩家赔付－历次实际转出本金＋历次对方退水＋历次该号对方赔付。平均净利润为49个号码等概率的均值；收益率基数是当前范围特码总流水。已转出后的当前风险和建议执行后的风险分别显示。

平均补打：以当前原始流水的49号平均为基准，超出金额四舍五入到分，减去同号已转出本金；负差额归零，不撤回旧转出。该方式不承诺满足亏损上限。

限亏最少金额：以实际转出后的剩余赔付为基础，按本次报价求达到亏损上限的最少整数元补打。

限亏优先已有：先仅允许补已有号码；无法达标时按剩余赔付由高到低添加新号码，优先最少新增号码，其次最少补打金额。号码限制指本次新增号码，不是历史累计号码或总操作次数。不能达标则明确提示，不擅自放宽亏损上限。

目标优化对每个赔付断点按有效覆盖号码数分段，搜索段内单调的利润；计算复杂度不随投注金额逐元增长。未来报价若形成49号全覆盖非负套利条件，不进行目标优化，提示核对报价，可用平均方案查看；实际批次仍可如实记录。

本功能只包含已解析的特码，同一日期市场混合不同已知期号会阻止计算。日期是账目业务日期，请按实际期次使用。未确定归属的公共转出不会推定为某个玩家的转出。未解析内容、其他玩法、对方违约和付款时差不纳入这个风险上限。

## 验证

覆盖分批不同赔率、按批次退水取整、重复提交、SQLite重新打开、空间/日期/市场/玩家隔离、公共与已删除账目持仓保留、原文减少不撤回、作废审计、整数目标与独立穷举交叉核对，以及完整49号与旧算法比较。

界面检查覆盖实际批次录入、新报价不改旧批次、追加投注自动补差、实际/建议口径切换、限制新增号码、市场切换、公共转出归属、非法金额和作废流程。

## 0.6.49 修正：三个入口独立

稳定转出与超出平均转出恢复原有的完整方案测算，均不扣已打出金额、不读取转出记录、不受分批数据加载失败影响。分批功能只在点击其入口后启用；两个原入口始终可见，可随时切回。已有批次和延迟返回的数据不会自动切换用户当前选择。

原方案表示按原投注重新测算的一整份方案；分批方案才是计入实际已打出后的补打建议。数据库历史批次保留。

## 0.6.52 · 删除记录与补打排序

- 展开「已打出记录（含作废）」，每批均提供「删除记录」。确认区显示该批金额；确认后永久移除本地批次，不要求填写原因。取消不改变记录。原「作废」入口仍保留，便于需要留痕的更正。
- 删除仅影响软件记录，不撤回实际转出。正常批次删除后，累计打出、对方赔付／退水、当前风险与补打差额自动重算；删除作废批次不改变计算金额。
- 删除限定当前空间以及批次日期、市场；不会清空其他记录或账目原文。浏览器预览与桌面数据库均支持。
- 「补打排序」默认需补打金额从高到低，金额相同时号码小的在前；也可选择号码升序或当前风险降序。仅调整清单顺序，不改变建议金额或策略。
- 复制补打清单、从方案打开核对清单沿用当前排序。已打开的核对清单保持原顺序，避免编辑时行位跳动。
- 特码集合和单个玩家的分批打出入口使用相同功能；原稳定转出与超出平均转出保持独立。
