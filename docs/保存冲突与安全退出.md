# 保存冲突与安全退出（v0.6.22）

## 问题原因

每个空间的账目使用数据库版本号防止旧窗口覆盖较新的数据。旧版在保存版本冲突后，关闭操作仍反复尝试相同的保存，又没有失败退出选项，因此无法正常退出。多版本同时打开、另一个进程写入或升级解析记录，都可能让窗口持有的版本号过期。

## 新版行为

- 同一数据目录的新版只运行一个实例，再次打开会显示已有窗口。该保护无法追溯约束尚未实现单实例锁的旧版，因此首次升级应先退出旧版。
- 没有修改的账目不再重复写入数据库；仅查看后退出不会主动覆盖其他更新。
- 保存冲突继续拒绝覆盖原数据库，同时把当前空间的全部原文、名称、日期和玩家绑定保存到单独的 `draft-recovery.sqlite`。
- 同次运行、同一空间只保留最新一份未保存副本。不同空间及之前运行的副本分开保留。保存成功后只清理本次运行当前空间的副本。
- 关闭时如保存失败，再次取当前窗口的最新原文进行备份，包括尚未提交的输入框文字。提示提供“返回编辑”和“保留原文副本并退出”。
- 副本写入失败时不提供退出选项，提示导出备份或复制原文。不会用强制退出掩盖保存失败。
- 取消退出后可以继续编辑、导出或重新退出，不重复叠加关闭提示。

## 如何恢复

再次打开后，右下角显示“发现未保存的原文副本”。点击“打开恢复副本”会创建并打开一个“恢复 · 原空间名”的独立空间。

来源空间与其账目保持原样。恢复空间具有独立的账目列表、全部统计、特码集合和平特肖集合。同名原文增加恢复序号，避免丢失任何一份。恢复成功后移除该条待恢复提示，恢复失败则保留副本可重试。

副本用于保全投注原文；未保存的赔率、退水设置、收件箱编辑不属于该原文副本。退出提示会说明这一点。如正在编辑这些设置，可选择返回编辑先处理。恢复空间中的赔付配置需按需要核对。

## 当前卡住的旧版

旧版不会因为生成了新安装包而自动获得修复。先在旧窗口点击“账目管理 → 导出全部账目”或原文区“导出备份”，确认 JSON 已保存。这个导出直接取当前界面原文，不依赖账目数据库保存成功。保全原文后再结束旧进程并打开新版；如需导入旧窗口备份，应先创建独立恢复空间，避免同名导入覆盖现有账目。

## 验证范围

覆盖保存冲突保留双方数据、跨重启恢复、同名原文保全、会话与空间隔离、副本写入失败、正常关闭、Cmd+Q、取消退出、重复点击关闭和后台停止失败。Mac打包检查同时验证真实IPC、恢复提示及独立空间恢复，并使用隔离数据库模拟保存冲突退出，检查退出后原数据库与最新原文副本均存在。
