# AI增量核验与缓存（v0.6.3）

录入第二笔投注时，前面未改动的投注不再重复调用AI。缓存保存在每个空间的本地SQLite中，按账目隔离，保存核验中、已完成、待确认、失败，以及用户确认的解释。缓存只减少核验请求，不合并或删除重复投注。

## 复用范围

以业务原文、玩家、市场、继承玩法、相关前文、跨行完整投注、业务日期、解析及核验规则、接口配置和表达词典共同确定缓存身份。行号不作为身份，插空行、移动位置或添加无关内容后，结果重新绑定到当前原文行。

修改号码、金额、市场或实际依赖的玩法声明时，只重新核验受影响的片段。跨行的号码与独立金额共同参与判断；尾部市场争议也参与判断。已存在的真实争议继续显示，不因命中缓存视为已确认。

## 进行中与失败

- 追加内容不取消正在进行的请求；相同账目的并发请求等待已有核验完成，再只处理新增片段。同批相同表达发送一次，结果绑定到各次出现，投注各自计账。
- 旧请求完成后先核对当前片段含义是否仍一致，再应用结果。修改了该笔原文时不使用旧解释。
- 核验失败、主动停止或应用关闭后中断的项目保留状态，继续打字不会自动重试；可点击“重试失败核验”或“重新核验此条”。前者只请求失败内容，后者更新指定表达的解释。
- 已有明确的本地解析继续按现有规则计账；AI失败不会自行变成投注争议。

## 清理与持久化

退出后重开可以复用缓存。清空本空间账目内容时，保留账目名称，清除对应片段缓存及核验历史；删除或被同名覆盖而移除的账目也清除对应记录。数据库中的清理代数阻止迟到的旧结果再次写回，新输入的相同文字属于新一轮核验。其他空间及其他账目的缓存不受影响。用户主动保存的表达规则和每日请求用量保留。

撤销清空仍使用原账目备份恢复原文；已经清除的片段缓存不恢复，后续按当前规则重新核验。

## 同版补充：每肖总额包号

“特包猪兔龙各十米一肖”表示猪、兔、龙各包10元，分别均分到各自的特码号码；共30元。马年猪08、20、32、44，兔04、16、28、40，龙03、15、27、39，每号2.5元。若包含本命生肖，该生肖的10元单独分给5个号码；其他肖单独分给4个号码，不将所有号码混在一起平均。

普通“奥特虎猪兔各十米一肖”继续按特肖每肖10元处理。金额无法均分到分或出现明确玩法冲突时仍提示。按每号分摊金额计算特码集合与赔付。
