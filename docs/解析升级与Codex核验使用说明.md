# 解析升级与 Codex 核验使用说明

版本：v0.4.6，2026-10-06。

## 本次解析修复

以下写法统一按新市场、四肖中特、整项200元计算，原文保持不变：

```text
新澳奥 四肖中特：龙牛狗蛇200
新澳奥 四肖中特 龙牛狗蛇200
新澳奥 4肖中特:龙牛狗蛇２００
新澳奥 四 肖 中 特：龙牛狗蛇二百
```

同一消息内也支持独立的玩法声明接续行：

```text
旧 四肖中特
龙牛狗蛇200
```

“四肖中特：”“旧 四肖中特：”“新 红波：”“新 天肖：”按业务字段识别；“小明：”仍识别为玩家。同一玩家继承市场，切换玩家默认新；一条已经完成的多肖中特之后，裸生肖仍沿用原本的默认特码口径，不无限延续多肖中特。

解析后会检查原文明确玩法和市场是否完整保留。数量不足、缺金额、矛盾玩法等进入待处理；无署名和客套话不增加警告。投注明细展开后显示市场、玩法、选号、计费与合计，并显示继承的玩法声明。

## 默认使用本机 Codex

桌面版的“AI核验”默认选择 **本机 Codex**，并自动核验疑难表达。已有明确配置的自定义API保留，可在“接口设置 → 核验入口”切换。

- 软件自动查找电脑上的 Codex 程序，沿用它现有的模型、服务连接与登录配置，不要求在松财再次填写API密钥。
- 这是通过本机程序调用模型服务，仍然需要联网并使用对应服务的额度，不是离线运行的本地模型，也不会继续当前聊天的上下文。
- 确定规则已覆盖的输入直接在本地计算；手动“核验整单”可以进一步核对全部投注。
- 核验保留完整业务前缀及必要的前文声明。已识别的玩家姓名不附带发送；业务原文中尚未识别的文字可能仍在片段内。图片仍只在本地OCR。
- Codex以一次性、只读、无交互模式运行；本次调用关闭命令执行、插件、应用连接、浏览器和多代理等能力，只接收文本并返回JSON。原文通过标准输入传递，不拼成Shell命令。
- 界面支持停止、重试、每日请求上限、结果缓存和人工选择候选。关闭软件会取消进行中的核验；原文改动后不采用过期响应。旧规则的表达记忆不直接复用。

如果自动找不到程序，在“Codex程序路径”填入已安装程序的绝对路径，再点击“测试连接”。若提示登录或凭据失效，先在本机Codex中恢复连接。Windows需要自行安装Codex；本客户端不附带Codex程序或账号凭据。

自定义API模式继续支持Chat Completions兼容服务，密钥仍通过系统保护存储。切换到本机Codex后，调用不会使用松财保存的自定义API密钥。

## 自动采用最新解析

读取数据库和导入旧账时，直接使用当前修正后的规则计算。取消“原解释／新解释”对比面板、勾选框和“采用新解释”按钮；已有v0.4.5待确认升级记录也自动生效。修改原文后继续自动计算，不因历史升级记录再次要求确认。

“原解释”是旧解析器产生的结果，不是另一种有效投注方式。例如下面三行直接计为600元（200＋200＋200）：

```text
新澳奥 四肖中特：龙牛狗蛇200
奥 四肖中特 龙牛狗蛇200
30.42各100.
```

账目ID、原标题、原文以及已有升级历史保留。已保存账目的自动标题在升级时固定，避免修复玩家识别后意外触发同名覆盖。缺金额、玩法互相冲突等真实问题继续提示，只影响对应投注。

已保存的赔付版本保留原来的数字；当前中奖数据使用新规则。历史列表可查看按原开奖、原赔率复算的差异，重新保存赔付生成独立版本。

## 分段小计与核验中断

“澳特:”属于业务声明，不是玩家名字。它可以作为一段投注的起点；其后“共…”核对该段小计，同时保留上次小计后累计的核对方式。“合计／总共”等仍核对同一消息的完整投注。只有具有明确起点的范围参与核对，不通过任意拼凑前几行消除差额。

例如：

```text
奥三中三01/02/03，30米
澳特:鼠牛号各5米
01,02各5米
03,04,05各5米。共65
澳特:06,07各十米共20米
```

马年下，第2至4行是40＋10＋15＝65元；第5行20元；全单115元。各段属于同一玩家。“共65”不应拿去和此前三中三一起比较。

历史AI核验若因停止或断网未完成，会重新检查本地规则是否仍有疑点。当前规则已经能够确定时正常计账，不再要求确认；界面显示“本地规则已确定”。真正存在的AI待确认结果和未解决歧义继续保留。核验失败不再误称“AI与本地解释有差异”。
