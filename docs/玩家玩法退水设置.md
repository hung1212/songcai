# 玩家退水独立菜单与玩法设置 · v0.6.19

顶部新增“玩家退水”菜单。原“开奖赔付”和本单“中奖数据”里的编辑表改成入口，退水集中在一个页面修改。

## 使用方式

左侧列出本空间账目中的玩家、空账目绑定的玩家、微信收件箱已入账的玩家，以及已保存配置的历史玩家。支持按玩家或账目名称搜索。原文有署名时沿用该署名的玩家身份；未署名账目按账目ID区分，改标题不改变退水归属。

选择玩家后可设置：

- **玩家默认退水**：每10,000元有效流水退多少元。旧版本已有的退水率保留为默认值。留空或填0不退水。
- **按玩法单独设置**：留空跟随该玩家默认值；填写0表示仅该玩法不退水；填写其他金额则覆盖默认值。逐项显示实际生效的百分比。

例如默认100元（1%），特码单独50元（0.5%），平特肖单独200元（2%），三中三单独0。若特码、平特肖、三中三有效流水分别为10,000、5,000、3,000元，另有二中二2,000元，则退水为50＋100＋0＋20＝170元。

支持按具体玩法设置：逐号特码、整项波色、半波、特肖／一肖中特、2至6肖中特、二中二、三中三、三中二、二中特、特串、2至5连肖、平特肖、平特尾、平码、平特号码、1至5粒任中、2至4连尾、5至10不中、大小单双／合单合双。别名归到同一玩法，胆拖与复式仍按所属玩法。

可搜索玩法，或勾选“只看单独设置”。切换玩家／功能页保留未保存草稿；“保存所有修改”统一保存所有编辑过的玩家。切换空间、退出程序前沿用工作区提交机制保存修改，非法金额或保存冲突会阻止提交并提示。重新载入有未保存内容时，可选择保留或放弃草稿。

## 计算和明细

有效流水沿用旧规则：中奖和未中奖投注均计入；退本金、待处理、缺开奖及其他待结算投注不计入。市场各自计算实际投注额，同一玩家各市场使用其对应玩法的退水率。

同一账目、同一玩家先累计各玩法的精确退水，再统一四舍五入到分；按余数将分位分配到市场和玩法明细，确保明细、单账目结算单、每日玩家合计相等。

每日结算与本单中奖数据新增可展开的“按玩家／玩法查看退水明细”：展示玩法、有效流水、实际退水率和退水额。应付＝赔付＋退水，玩家净输赢＝应付－投注。全部账目总额、账目净输赢及盈利排序同步。按玩法统计仍展示不含退水的玩法赔付视角，保持原有提示。

结算单预览和截图在“退水合计”下直接列出各玩法明细，例如特码退1.5元、特肖退3元；平码与平特肖分别列示。每行显示玩法、有效流水、实际退水率和退水额。同玩法跨玩家／市场合并，不同费率标记“多档退水率”；未退水的玩法不显示。已参与退水但舍入不足1分的玩法保留0元。

明细取自已保存的结算结果，合计与总退水一致，不再次按流水乘费率计算。历史快照未留存玩法明细的部分显示“未分类退水”，不套用现有设置补算。中奖和退水明细各每18行分页，所有页保留全单总额；未展示的明细提示见其他页。

## 保存和兼容

- 配置保存在当前空间SQLite，重启保留；空间间独立，清空投注内容不清除配置。
- 兼容旧的玩家统一退水配置；历史赔付快照保留原金额，不按新设置补算。
- 保存时只合并用户修改过的玩家／玩法字段，保留其他玩家和赔率更新；相同字段被并行修改时提示重新核对，不静默覆盖。
- 金额使用整数分和整数比例计算，输入范围0至10,000元、最多两位小数。

## 验证

测试覆盖默认继承、覆盖0、清空覆盖恢复默认、细分玩法映射、多玩家／市场／账目汇总及舍入、待结算和退款排除、空账目身份、字段级冲突、SQLite持久化、浏览器空间隔离、微信已入账名册、历史保护及结算截图。界面检查使用隔离模拟账目，不改动真实账目。
