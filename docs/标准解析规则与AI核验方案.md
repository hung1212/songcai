# 标准解析规则与 AI 核验方案

日期：2026-10-05。状态：已按用户确认实施于 v0.4.4。接口默认关闭；当前未配置真实服务商，也未向 AI 服务商发送用户投注原文。实现范围与操作见[AI核验与最近开奖使用说明](AI核验与最近开奖使用说明.md)。

2026-10-06复核补充：v0.4.4曾存在业务前缀被误识别为玩家、声明续行丢失，以及AI输入缺少原始业务前缀的问题。v0.4.5已修复，并按用户要求默认接入本机Codex。诊断依据见[解析结构与静默误判治理方案](解析结构与静默误判治理方案.md)，本版操作见[解析升级与Codex核验使用说明](解析升级与Codex核验使用说明.md)。

建议采用“本地标准规则先解析，AI 辅助识别陌生表达，本地校验后计算”的方式。标准规则负责确定业务含义，AI 提供结构化解释与原文依据，金额、生肖展开号码、中奖和赔付由程序按已确认规则执行。

## 1. 本次明确的业务规则与现状

原文：`新奥，牛鼠数各十五`。

| 项目 | 解释 |
| --- | --- |
| 市场 | “新奥”＝新市场 |
| 玩法 | “牛鼠数”指牛、鼠对应的特码号码 |
| 计费单位 | “各”＝每个展开号码 |
| 单价 | “十五”＝15元 |
| 2026马年牛号码 | 06、18、30、42 |
| 2026马年鼠号码 | 07、19、31、43 |
| 总投注 | 8个号码 × 15元＝120元 |

2026-10-05 对 v0.4.3 当前源码进行只读、内存解析验证：

- 单独输入这条，得到特码120元；但是目前主要依靠默认特码，而不是将“数”识别为明确的玩法依据。
- 上一行是 `平特牛各十` 时，这条会错误继承为平特肖，算成30元。
- `特肖牛鼠数各十五` 当前会按特肖30元计算，没有揭示“特肖”和逐号表达之间的冲突。

因此需要补足标准语义和冲突检查，不能仅以“成功解析、没有报错”作为正确依据。

## 2. 统一的解析过程

原文 → 消息与玩家上下文 → 词语及结构识别 → 玩法和计费单位判定 → 标准投注对象 → 本地计算与校验 → 必要时 AI 核验 → 确认结果。

每一步保留原文位置和判断依据。既保留原文，也保留规范化后的写法；未知文字不能先删掉再交给 AI，否则可能丢失关键信息。

### 2.1 先识别结构，再识别数字

区分市场、玩法、选号、组合大小、单价、合计和备注，避免把“二中二”的“二”当作金额，把“十五元”的“十五”当作球号。

维护可版本化的标准词典：

- 市场别名：如新奥、新澳、新澳门归一到“新”，同时保留原词。
- 玩法词：特码、特肖、平特、连肖、二中二等，采用完整词和上下文匹配。
- 计费词：数、号码、每号、每肖、每组、整项等，限定适用语境。
- 金额词：已有中文金额与单位继续支持；“壹拾伍”等财务数字可纳入确定转换规则。
- 待确认俗称：谐音、动物代称、OCR疑似错字和玩家独有缩写，先作为候选，确认后再加入别名表。

AI 负责提出新别名候选，不直接把一次猜测升级为全局标准。

### 2.2 玩法判定规则

| 编号 | 条件 | 标准处理 |
| --- | --- | --- |
| R01 | 生肖集合后紧跟“数／号码／数字”，并形成逐号投注表达，如“牛鼠数各十五” | 将生肖展开为特码号码，按每号计费 |
| R02 | 明确“各号／每号／每个号码”等单位，且与选号类型相容 | 识别为逐号计费依据；结合玩法检查是否相容 |
| R03 | 明确特肖、连肖、平特等玩法，计费单位相容 | 按明确玩法解析 |
| R04 | 同一笔出现相互矛盾的明确证据，如“特肖牛鼠数各十五” | 标为玩法／计费单位冲突，列出不同解释，暂不自动定案 |
| R05 | 当前行存在明确的逐号特码表达，而上一行是平特或连肖 | 当前行的新表达终止旧玩法继承；市场仍独立按市场规则继承 |
| R06 | 当前行没有明确玩法或计费依据 | 使用已确认的上下文继承规则；无上下文时沿用现有默认口径 |
| R07 | 缺金额、缺选号、取消或修改指令，无法唯一解释 | 保留待处理，不让 AI 补造缺失数字 |

不能使用“出现任意一个‘数’字就判为特码”的全局替换。例如“单数”“双数”“合数”应按完整词理解，备注中的“数”也不是玩法声明。

市场继承与玩法继承分别处理。玩家切换后市场回到“新”；多市场分别计费；无署名按本单玩家，不恢复归属警告。

### 2.3 保持已有业务口径

| 输入 | 预期处理 |
| --- | --- |
| 新奥，牛鼠数各十五 | 新市场，逐号特码，马年120元 |
| 特肖牛鼠各十五 | 两个特肖各15元，共30元 |
| 特肖牛鼠数各十五 | 冲突候选：逐肖30元／逐号120元，需明确含义 |
| 平特牛各十，下一行“牛鼠数各十五” | 前一笔平特10元；后一笔新声明逐号特码120元 |
| 牛鼠各十五（无其他上下文） | 沿用当前默认逐号特码口径；本次没有将裸生肖改成特肖 |
| 红波100 | 整项波色100元 |
| 红波各100 | 17个特码号码，各100元，共1700元 |
| 天肖各100 | 按农历生肖表展开号码，2026马年2500元 |
| 两边，牛鼠数各十五 | 新120元、旧120元，共240元 |
| 特肖三中三1 2 100. | 玩法冲突，继续提示 |

生肖展开依据账目的业务日期和农历年；AI 不负责生成生肖号码表。五行使用已确认的固定表。

## 3. AI 调用方案对比

| 方案 | 作用 | 成本与局限 | 建议 |
| --- | --- | --- | --- |
| 仅本地规则 | 已知标准表达快速、稳定、离线计算 | 新俗称需要补充规则 | 必须保留为基础 |
| 本地规则＋疑难 AI 核验 | 检查未知词、上下文冲突、异常计费和可疑成功解析 | 调用较少，但仍需识别哪些输入有风险 | 推荐默认 |
| 所有投注都经过规则与 AI 双重核验 | 可发现部分规则漏检 | 费用、等待和原文外发量更高；AI也会误判 | 可选严格模式 |
| 开奖后只核验已判中奖记录 | 核验量较小 | 已误判成未中奖的记录不会进入核验，可能漏赔 | 不建议作为唯一核验方式 |

v0.4.4 按本方案实现“录入后核验疑难表达”，同时提供手动整单核验；进入中奖数据时复用已确认的解释。在最终保存赔付前检查是否仍有未解决的语义争议。

### 3.1 哪些情况调用 AI

- 无法识别的俗称、缩写、谐音或OCR疑似错字，且可能影响玩法、号码或金额。
- 多个玩法／计费单位冲突，或当前行与上文继承冲突。
- 虽然解析成功，但存在未解释的疑似业务词，或者结果依赖默认／继承而没有充分依据。
- 声明的数量、合计与程序计算不一致。
- 用户主动点击“AI核验本单”；严格模式可核验整单。

标准规则已唯一覆盖的输入不必每次调用。例如补足 R01 后，这次“牛鼠数各十五”可以直接由本地规则确定。普通客套话和无关文字不触发警告。

### 3.2 AI 返回什么

返回结构化候选解释，至少包含：

- 原文片段及其位置、市场、玩法、选号类别和选项。
- 每号／每肖／每组／整项计费单位，金额文字和建议规范值。
- 各关键字段的原文依据，使用到的标准规则编号。
- 无法确定的字段、其他候选解释及差异原因。

不要求 AI 直接输出最终赔付。对本次样例，其职责是解释为“新市场、特码、选号来源为牛鼠、每号十五元”；程序负责展开8个号码、转换1500分、计算120元，再按对应市场已确认开奖和赔率计算赔付。

### 3.3 如何采用核验结果

| 核验结果 | 处理 |
| --- | --- |
| AI与确定规则一致 | 记录“核验一致”；不是保证绝对正确 |
| AI建议仅是已确认规则允许的规范化，所有关键字段都有依据且唯一 | 可自动采用，保留规范化记录 |
| 新的未确认别名会影响号码、市场、玩法或金额 | 展示候选和金额差异，批量人工确认 |
| AI与明确规则冲突 | 保留标准依据和AI建议，不静默改写，显示待确认项 |
| AI无法确定、返回结构无效或证据不能对应原文 | 不采纳；必要时保留待处理 |
| API超时、限流或断网 | 本地确定部分继续使用；依赖核验的部分保持待核验，可重试 |

不得仅凭模型自报“99%置信度”入账。自动采用依赖具体的规则、字段依据和本地校验。新模型、新提示词先通过固定样例验收再扩大自动采用范围。

## 4. 减少手动操作的设计

1. 粘贴、导入文字或OCR结果后，先显示本地解析，后台排队核验疑难项；不在每次输入按键时请求API。
2. 批量处理多个疑难片段，并保留各自玩家、消息和账目边界，避免上下文串单。
3. 只集中显示有实质差异的项目。例如一行显示“按特肖30元／按特码120元”，并标出原文依据“数”。
4. 重复疑难写法按相同上下文归组，允许一次确认一组；上下文或业务日期不同的输入不能只凭原文相同批量套用。
5. 用户可把确认过的表达保存为“通用别名”或“仅该玩家适用的别名”；默认一次确认只作用于当前内容。
6. 核验完成后按账目更新解析版本；进入中奖数据时复用核验结果，避免切换账目或标签就重复调用。

缓存条件包含原文、有效上下文、业务日期、规则与别名版本、模型和提示词版本。每次应用缓存仍绑定当前账目ID和消息ID；编辑后取消或丢弃旧请求响应，防止把旧答案写进新原文。

## 5. 中奖与赔付如何衔接

先确认投注含义，再由本地程序计算中奖与赔付：

`已确认投注版本 ＋ 对应市场与日期的开奖 ＋ 已确认赔率 → 本账目中奖明细与应付金额`

AI核验不能替代此前的多网站开奖核对，也不能自行选定有差异的开奖结果。

保存赔付时关联投注解析版本、AI核验或人工确认记录、规则版本、开奖依据和赔率快照。原文、关键解释或赔率变更后重新计算；已保存的旧赔付版本不自动覆盖。仍有业务歧义的账目不能标为结算完成。

如果希望增加“开奖后核验”，建议作为第二道检查：结算前核查本单全部投注解释和规则执行，而不是只把已中奖记录交给AI检查。AI仍不作为算术或开奖结果的权威来源。

## 6. 接口与本地保存

首版提供API服务地址、模型、密钥、启用模式、连接测试和用量上限。先适配一种支持结构化输出的接口协议，保留服务商适配层；具体服务商和费用需选定后再核验，不在方案阶段猜测价格或速度。

- 网络请求由桌面主进程执行；API密钥使用操作系统凭据保护能力保存，不写入账目、普通导出或日志。
- 启用时说明哪些内容会交给选定服务商。默认只发送核验片段、必要的前文、匿名玩家标识、日期和相关业务规则，不发送完整通讯录或无关聊天。
- 原文、AI候选、人工决定、规则版本和处理状态保存在本地SQLite。图片首版继续本地OCR，再对识别文本核验；原图核对保留在本地。
- AI只读取文本并返回数据，不提供文件、系统操作或API配置修改权限。原文里的“忽略规则”等句子视为输入内容，不是执行指令。
- 支持有限并发、超时、限流重试、取消和预算上限；所有失败都不能造成重复入账或重复计费。

## 7. 推荐实施顺序与验收

**第一步：标准规则与解释依据。** 将“生肖＋数”的语义、上下文继承和冲突处理落入统一规则；保留每个字段的原文证据。先修复可确定的问题。

**第二步：AI辅助核验。** 增加接口设置、疑难队列、结构化候选、本地校验、差异确认与缓存。初期对新别名只提出建议，积累经人工确认的样例。

**第三步：有限自动采用。** 将已确认且无歧义的表达加入版本化词典，在样例验证后自动识别；提供可选的整单核验。保留历史、撤销本次解释及重新计算能力。

验收至少覆盖：

- 本次样例单独输入、接在平特／连肖后、跨消息和跨玩家时均正确；“数”不影响独立的市场继承。
- “特肖＋数”冲突、单数／双数完整词、备注中的“数”、中文金额与未知俗称不会错误套用。
- 2026-02-16与2026-02-17的马号码数量随农历年切换，原始文本及计费依据可追溯。
- 规则和AI意见一致、不一致、无依据补数、缺金额、伪造指令等输入均按上述处理。
- 断网、超时、重复请求、编辑期间返回、换账目与缓存复用，不串单、不重复入账。
- 不只统计“能解析多少条”，还逐项对照人工标注的玩法、市场、计费单位、选号、金额和赔付，分别记录自动正确、需确认和错误采用情况。

v0.4.4 已实现标准规则、桌面接口配置、候选确认、同上下文批量确认、完整表达记忆及赔付衔接。服务商、模型与密钥由用户在软件内配置；当前通过模拟服务验证接口行为，尚未进行真实服务商联调。首版表达记忆严格匹配完整片段和上下文，不把未经验证的子词替换自动推广。


## 2026-10-07 后续规则确认（R19—R21）
