# 微信收件箱第一版（v0.3.0）

日期：2026-10-05。范围按用户确认：**基础收件箱＋读取当前打开的收藏**。本版不包含直接私聊采集或收藏列表整批自动打开。

## 打开软件

- Intel Mac：[已解压的松财.app](../desktop-client/release/松财-0.3.0-mac-x64/松财.app)。先用 ⌘Q 完全退出旧版，再打开新版。
- Intel Mac 压缩包：[松财-0.3.0-mac-x64.zip](../desktop-client/release/松财-0.3.0-mac-x64.zip)。
- Windows x64：[松财-0.3.0-windows-x64.zip](../desktop-client/release/松财-0.3.0-windows-x64.zip)。解压整个文件夹，再打开松财.exe；尚未 Windows 真机验证。

新版放在独立版本目录，没有替换旧版应用。投注账目原文会迁移到本地 SQLite；微信收件箱仍单独保存。

## 文字和图片录入

1. 打开左侧“微信收件箱”。先填写本批业务日期、微信来源备注和绑定玩家。
2. 从微信复制文字或图片，点击“粘贴微信记录”；也可以“添加文字”或一次“导入图片”。
3. 图片在本地识别，原图保留。左侧查看原图／逐页原始 OCR，右侧校正识别文本。
4. 查看解析预览，核对玩家、业务日期、市场起点和金额，勾选对应核对项。
5. 点击“确认入账”，或在列表选择多份记录后点击“确认选中合格项”。异常项留待核对，合格项独立入账。

同一份记录支持追加文字编辑和“补充图片”。同一原始段中的市场声明与后续省略行应放在一起；新建另一份记录默认新市场，不根据玩家名恢复其他记录里的旧市场。缺少前文时，应在识别文本开头补上已核实的市场。

“微信来源备注”是用户确认的本地标记，不是自动提取的微信账号 ID。确认来源后，桌面版会保存该来源与玩家的映射，后续在来源下拉中复用。同名但不同人应使用不同来源备注和账目名称。

一份资料含多位玩家时，整理成明确的“姓名：正文”并启用“使用原文中的多玩家署名”，逐一核对归属。默认情况下，原文署名与绑定玩家冲突会阻止入账。

## OCR 数字间距修复（Mac）

v0.3.0 结合中文识别、数字词框和字符坐标，在数字内容一致且图像有分隔证据时补回空格。例如 `231` 恢复为原图中的 `23 1`，`42123412` 恢复为 `42 1 23 41 2`。不按两位数盲拆，也不删除重复号码；金额 `100`、`1000`、`10.50` 保持完整。Windows OCR 暂沿用原系统识别，本次尚未实现同样的字符几何恢复。

每页仍保留原始 OCR；“已按原图间距恢复”展开可查看前后变化。识别把握较低的文字会提示核对。**高亮或补空格不代表整笔玩法、号码已正确**：用户截图的小字“三中二”仍可能被识别为“三中三”，请对照原图校正。

旧记录可以点击“用原图重新识别（新草稿）”。软件新建识别稿，原记录和手动校正不变，并提示相同图片重复来源。核对后只入账一次；不再使用的旧草稿可跳过。此功能不会自动更改已确认金额。

## 读取当前收藏

本版采用**窗口预览＋正文框选＋自动滚动截图＋本地 OCR**。没有读取微信数据库，也没有接入第三方自动回复工具。收藏正文的 AX 直接结构化提取尚未实现。

1. 在电脑微信中打开一份目标收藏的详情，展开要读取的聊天记录，滚到这份资料的开头。
2. 在松财填写玩家、业务日期与来源，点击“读取当前收藏”。
3. 首次在 Mac 上按界面提示，为松财开启“屏幕录制”和“辅助功能”。若授权后仍不可读，完全退出松财后重新打开。系统权限需要用户自己授予，本次开发未替用户修改权限。
4. 选择目标微信窗口，点击“获取预览”。收藏若显示在微信主窗口内，也可以选择该主窗口。
5. 在预览上拖出正文区域，避开标题、左侧列表、输入框和滚动条。区域决定截图及滚动位置。
6. 勾选已回到读取起点，建议第一次选“1页（试读）”核对效果，再读取多页。
7. 采集时保持目标微信窗口在前台，不切换收藏或操作鼠标。软件逐页保存截图和识别内容。
8. 停止后对照每页原图核对识别文本、跨页衔接和读取范围，补齐缺失内容，再确认入账。

切换到其他窗口、窗口大小或位置变化、目标关闭、达到页数上限、识别失败等会结束当前采集并保留已保存内容。画面不再变化只会提示“范围待核对”，**不会自动宣称已经读完收藏**。

“停止并保留进度”用于主动中断。“继续读这份”可在原微信窗口仍存在时，从包含上一页重叠内容的位置续读；需要重新预览和框选。继续读取保留已经校正的文字。微信重启导致窗口身份改变时，创建新的独立记录并核对重复部分。

本版不会自动打开下一份收藏。图片读取的是当前画面中的内容；模糊缩略图、未展开图片、嵌套聊天卡片和屏幕外未加载内容不能视为已获取原件。可将清晰原图通过“补充图片”加进同一份记录。

## 核对、重复和账目

- 解析预览不等于入账。只有已确认记录进入收件箱顶部金额及下方“玩家 × 市场账目”。
- 该汇总只统计所选日期的微信收件箱记录；原“投注账目”的文本仍在原界面统计，避免不知情地把同一来源重复合并。
- 相同正文不会直接删除。来源玩家和日期相同且文字／图片相同时，显示疑似重复；真实的第二次投注可以明确确认，重复采集可以跳过。
- 跨页重叠只生成合并建议，逐页原文和截图保留。重复句式、无法确认连续性等情况提示核对。
- 重复点击确认、程序重启或同一备份重复恢复，不会重复累计同一个本地记录 ID。
- 改动文字、玩家、业务日期或来源后，原来的核对勾选失效，需要按最新内容核对。
- 已入账记录锁定。本版尚无撤单、账目冲正或赔付；含“取消／改成”等指令的原文会阻止直接入账，应先人工明确最终投注。

## 保存和备份

桌面版在应用数据目录的 `wechat-inbox/` 下保存 SQLite 数据库和独立图片附件。没有原文本工作区的200份文档上限；列表每页40份。浏览器预览使用当前浏览器的 IndexedDB，与桌面数据分开，不能使用系统 OCR 和收藏读取。

点击“导出含原图备份”导出所选日期范围，清空日期筛选可导出全部。该 JSON 包含原文、校正文本、日期、来源、核对状态、已确认结果及原图。每个备份最多200MB，大量图片时按日期拆分。

桌面版“恢复备份”保留原 ID：

- 已存在的相同记录跳过。
- 同 ID 但内容或状态冲突时保留本机版本，报告冲突数量。
- 图片缺失、校验不一致或结构无效时拒绝恢复新数据。
- 备份中的已入账结果若与当前规则／核对状态不一致，恢复为待核对，不自动加入金额。

收件箱备份通过“恢复备份”打开，不使用原文本页的“导入账单”。关闭软件会先保存编辑内容、停止采集并保存已有进度，然后完全退出。

## 验证结果和当前边界

- **156项自动化测试通过**：包含原解析规则、玩家市场继承、确认前不计账、真实重复保留、确认防重、并发版本检查、事务回滚、备份恢复、原图保留、采集中断、续读及模拟窗口切换。
- **Intel Mac 打包程序真实启动检查通过**：使用隔离测试资料验证页面、样式、收件箱菜单、真实 IPC、SQLite 入账、防重复确认以及关闭保存。
- **Mac 本地 Vision OCR 12行回归通过**：恢复一位数、重复选号、混合号码列表的间隔，并检查连续数字、金额、小数和日期时间不被误拆。见[OCR回归报告](../desktop-client/reports/ocr-spacing.json)与[用户截图目标号码验证](../desktop-client/reports/ocr-user-spacing.json)。这不代表所有图像或金额的准确率验收。
- 浏览器界面核对了文字输入、旧市场400元预览、确认前后金额、刷新恢复、图片保存与校对后的2100元预览；测试记录放在独立本机端口的浏览器工作区。
- **真实微信4.1.13收藏采集尚未端到端验收**，没有读取用户实际聊天。自动滚动、窗口形态、模糊图片、嵌套记录仍需授权后通过试读验证。
- Windows 已打包并提供系统 OCR／窗口采集适配源码，尚无真机运行结论。OCR需要安装中文语言资源；超出系统识别尺寸的长图需拆分。第一版未更新 Apple Silicon 安装包。
