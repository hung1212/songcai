## 已计入金额中的两个重点问题

### 第411行：明确分组被展成复式，多计900元

原文：`香港三中三20-32-36#18-34-45各组50。三中三二中二20.32.36.18.34.45各5。合计275。`

当前首部分把两个三号码组混成6选3，按20组×50计1000元，再加100元和75元，合计1175元。这三笔目前均为已解析状态，合计不符只是普通提醒。

保留#的分组语义后：两组三中三×50=100元，后面6选3×5=100元、6选2×5=75元，总计275元，恰好符合原文合计。分组结构和合计是相互支持的证据，不能仅为了凑275而任意选择解释。

### 第316–317行：末尾号码被当金额

原文前一行是10个号码，下一行“各数20元”。当前前一行被当成9个号码各47元，已计423元；后一行报缺选号。按完整两行应是10×20=200元。

这说明只修报错的第317行不够，还要把依赖它的第316行一并重新判断。应优先确定金额的作用范围，再允许单行末尾数字简写，避免先把47当钱。

## 仍需业务约定或完整上下文的写法

| 类型 | 实际例子 | 判断边界 |
| --- | --- | --- |
| 疑似错字 | `各6O.米` | 很可能为60元，但O变0会改变财务输入。限定金额区域、列出纠正证据；可确认一次适用规则，不能在任意字符中直接替换 |
| 玩法别称 | `四中肖…`、`三中肖…`、下一行`五中各30` | 很像四连肖、三连肖、五连肖，但现有规则未定义这组别称；“五中”还缺本行选号，需要确认继承范围 |
| 省略玩法的串／打 | `鼠串狗各数5`、`马串羊狗各10`、`猪打狗、狗打鸡每组15斤外` | 交叉配对能理解，但二中二和特串中奖条件、赔率不同。根据同消息明确玩法或经确认的该来源习惯选择，不仅凭“串”字猜玩法 |
| 多玩法互拖 | `新二连特连09.21.45串22.12.36.48各20元` | 可提出二中二、特串各12组的候选，但“特连”别称及是否两种都投需有约定 |
| 段尾市场 | `9特码100香港`、`特羊狗虎兔各5元，香港` | 单笔尾注与整段尾注须区分。用户此前要求过后置市场发生归属争议时待处理，不能为了减少提示直接推翻该规则 |
| 多市场尾注 | `22，21各10元，新澳门。香港` | 可能两边都投，也可能文字修订；没有明确规则时保留一次确认 |
| 跨空行共享单价 | 三中二三号码一组，隔空行再列数组，最后`各5元，新澳门` | 形状像多组共用单价，但用户此前要求空行重置市场和玩法。需要区分“消息边界”与“消息内排版空行”，不能全局跨空行继承 |
| 一字多义 | `13一22各10米` | 很像13、22两个号，但“一”也可能构成范围标记。应给明确候选，不能用通用替换掩盖差异 |
| 包波色 | `包红波280米` | 需要区分整项波色与逐号分摊。若分到17个红波号，280÷17不能精确到分，还涉及余数策略 |
| 口语量词 | `…各十个…各二十个` | 很可能是各10元、各20元，但“个”是金额口语还是数量，应记录该来源的业务约定 |

## 方案对比与建议

| 方案 | 优点 | 不足 | 建议 |
| --- | --- | --- | --- |
| 继续逐条补正则 | 熟悉例子见效快 | 换个标点、顺序或组合又失败；金额与分组可能先被错误切分 | 只用于低风险词法补齐与紧急修复 |
| 全部交给AI自动入账 | 对口语和上下文理解灵活 | 相同字样可能有多种财务含义；模型自报信心不能证明正确，可能静默漏笔或改金额 | 不作为单独决策链 |
| 结构化规则＋上下文AI候选＋本地验证＋来源习惯 | 确定内容自动通过，真正不确定的才询问；确认能复用 | 需完善结构、证据、规则作用范围与回归数据 | 推荐方向 |

推荐流程：原文保留 → 识别消息与小组边界 → 提取市场／玩法／选号／金额／分组证据 → 规则直接处理确定表达 → AI处理剩余候选 → 本地展开、计数、金额及覆盖检查 → 唯一受支持的解释自动入账，其他只询问差异点。

### 1. 先修结构，保留原文证据

- 将消息、段落、子句、组别分开。空行可提示边界，但不能替代微信的真实消息边界；从收藏导入时保留发送人、消息ID和消息内换行。
- “已明确市场”“消息内继承市场”“默认新澳”分开存储。更细的来源证据有利于判断尾注，但行为变更仍应遵守已确认的业务规则。
- 先确定明确单价及其范围，再切投注。多玩法共享号码、每组金额和尾部市场都应有明确结构，而不是全靠字符串清洗。
- 已有的串、拖、对打只是组合运算；玩法仍单独决定。选号可由数字、生肖、头尾混合构成，两侧分别展开，然后计算合法组合。

### 2. AI输出可核验的候选，不直接修改原文或总金额

现在AI主要按单行核验，附带少量前文声明；无法充分看到跨空行分组、同句多个玩法及尾部共享字段。应以完整消息为最小上下文，并保留号码、金额、市场、玩法各自的原文位置。

AI返回候选结构及依据，由本地代码计算号码、组合、投注金额、中奖和退水。自动采用应同时满足：

- 原文有效投注全部被覆盖，且没有重复计入；正常声明或装饰文字有明确解释。
- 金额与号码有可定位依据，不互相占用同一段文字；没有补造市场、金额或玩法。
- 与用户明确规则、实际上下文和已确认来源习惯相容。
- 原文“两组”“合计275”等声明与计算一致；若声明范围自身不明，应明确列出候选范围。
- 只剩一个实质上受支持的解释；如仍有两个可能，即使模型说“99%确定”也不自动选择。

若两个解释投注总额相同，但玩法、市场或中奖条件不同，仍属于实质冲突。

当前代码对“AI与本地完全一致”可直接通过，但“AI给了一个修正后的新解释”一般仍进入待确认。因此仅换强模型或修改提示词，并不能解决确认次数多的问题；需要增加上述受控自动采用通道。

### 3. 确认一次，形成有范围的习惯规则

当前已有核验缓存、表达规则、同表达批量确认，但主要匹配完整文案、上下文。应逐步支持带类型的表达模板：例如生肖参数、号码参数、金额参数；金额变化后重新校验，不复用旧金额。

规则默认限定当前空间和可靠识别的来源／玩家，可查看、停用、撤销；支持用户明确推广到全局。不能因为账单都叫“副号”，就断定所有转发内容都来自同一真实玩家。生肖展开始终使用该账单农历年度，不把今年的号码固化到模板。

### 4. 让剩余人工操作只处理关键差异

- 同一条原文只显示一个待处理卡片，汇总本地原因和AI状态。
- “AI处理中”“需要确认”“已自动识别”分开显示；AI失败不是业务错误，但本来存在的真实歧义也不能因失败而被隐藏。
- 按同一原因、同一来源、同一适用范围分组处理。显示涉及条数、金额影响和例外，不盲目一键确认全部。
- 把“请核对玩法、选号、单位、金额”改成具体选择，例如“这里是二中二还是特串”；给出组数、投注金额及市场，减少来回修改原文。
- 自动解释可展开查看依据和标准读法，并可撤销。保留历史结算快照；账单原文不被自动重写。

### 5. 同时验证正确率和自动处理率

以本次真实原文建立固定验收集，并纳入已解析内容，不能只测试报错行。每条标注市场、玩法、号码／生肖、分组、单价、总额与来源范围；为相近但含义不同的反例单独设断言。

测试标点、中文数字、语序、连续／分行、多笔组合等变体。大数小数、平码特码、每肖每号、单市场多市场即使总额相等，也应按完整结构比对。

第一阶段先将新解释放在对照结果中，比较当前与新方案的金额和玩法差异，验收后才开放自动采用。统计人工确认次数、自动通过比例、确认后仍需纠正的比例，以及错误金额影响；不把隐藏警告算作准确率提升。

## 建议实施顺序

1. 先处理第411行错误分组、第316–317行金额绑定，并修复同句继承依据误报；增加确定合计或组数冲突的处理策略，避免明显不符的解释作为已确认金额使用。
2. 完成17行明确技术修复方向及正反例验收；合并重复提示。修复必须回归这份账单和已有样例，不能只验证单条输入不报错。
3. 归纳剩余写法的少数业务约定，集中确认别称、串／打缺省玩法和消息尾注范围；确认后用有范围的模板覆盖同类表达。
4. 增加按消息的AI候选与本地自动验证，开启可解释、可撤销的自动采用。

优先目标是减少实际需要人做决定的次数，同时拦住错误入账。尚未完成标注、实现和回归前，不承诺将82项降至固定数量或达到某个百分比准确率。
